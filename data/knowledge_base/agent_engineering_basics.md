# Agent 工程基础（演示知识库）

## 任务规划与工具调用
Agent 应把用户目标转成可检查的步骤，而不是把所有工作都交给一次长 Prompt。工具应有明确名称、输入 Schema、权限边界、超时和错误处理。模型可以建议调用工具，但应用代码负责验证参数并执行。

## 动态上下文与检索
每次模型调用不应无条件携带全部历史。应根据当前意图选择相关工具描述、同一用户同一会话的相关历史，以及必要的文档证据。检索结果要限制数量和长度，并记录召回来源。关键词召回是可解释的基线；语料变大后可替换为 BM25 或向量检索。

## 结构化输出
对需要程序消费的模型输出，应定义 Pydantic Schema 并在应用端校验。模型输出 JSON 并不等于输出一定正确；校验失败时可以进行一次有上限的修复重试。多次失败应降级或返回可解释错误，不能静默接受错误结构。

## 重试、降级与恢复
只对超时、连接错误、限流和部分服务端错误做有限重试。认证错误和参数错误通常应立即失败。退避重试应设置最大次数与延迟上限。备用模型、本地规则或缓存可作为降级路径，但必须标明结果来源与局限。

## 评测与可观测性
至少记录任务类型、调用工具、节点耗时、重试次数、缓存命中、错误类型和最终状态。用固定评测集比较路由正确率、工具成功率、结构化输出通过率、任务完成率、延迟和成本；不要只靠主观感觉判断升级是否有效。

# TaskPilot Agent Platform 技术审查报告（v3.0）

> 审查对象：`taskpilot-industrial/`（v2.0.0-industrial）及其配套教程、README、测试与运行产物。
> 审查日期：2026-11-04。
> 审查方式：源码逐文件阅读 + 本地实际运行测试 + 两个只读探针复现缺陷；不以文档自述作为能力证据。
> 结论口径：**只把“代码里存在、能被测试或探针复现”的能力算作已实现**。设计稿、README 描述、注释中的未来计划均不计入。

---

## 0. 一句话结论

TaskPilot 已经从一个“固定流水线的 LangGraph 教学 Demo”，升级为一个**单机、同步执行、Mock 驱动验证的 Agent 可靠性工程原型**：ReAct 有界循环、分类重试、三态熔断、SQLite 工具幂等、LangGraph 检查点恢复都有真实代码和测试证据；但它**不是生产级系统**，也**没有真实模型质量证据**，任务调度、任务租约、取消、多租户、评测体系仍未落地。

当前真实水平：**L2–L3 之间**（L0 教学 Demo / L1 可运行原型 / L2 有工程约束的单机原型 / L3 可复现的工程作品集 / L4 生产级）。  
更准确的说法是：**“机制层”接近 L3，“系统层”仍在 L2。**

### 1.2 只读探针

为了验证“文档没写、但代码可能有问题”的地方，另外跑了两个不修改项目源码的探针：

**探针 A：跨用户复用 `Idempotency-Key`**

```text
alice: 200 <task_id>  goal=计算 1 + 1
bob  : 200 <同一个 task_id>  goal=计算 1 + 1
same task_id: True
```

结论：`POST /tasks` 只按 `Idempotency-Key` 查任务，没有把 `user_id` 纳入作用域。Bob 用同一个 key 提交，拿到的是 Alice 的任务。这是**已复现的越权/数据泄露缺陷**，不是理论风险。

**探针 B：`GET /tasks` 的用户隔离**

```text
users visible to bob via GET /tasks: ['alice', 'bob']
alice reading bob task: 404
```

结论：单任务详情接口有 `user_id` 校验，但列表接口没有；任何持有 API Token 的调用者都能看到所有用户的目标。**接口间权限不一致**。

## 3. 文档与代码一致性核对

这是本轮审查的重点之一：**教程/README 里写的，是否真是代码做的。**

| 文档表述 | 代码事实 | 判定 |
|---|---|---|
| “64 个测试，含真实子进程崩溃” | `pytest` 64 passed；崩溃测试用 `subprocess` + `os._exit(42)` | 一致（E1/E2） |
| “6 线程并发只产生 1 个副作用” | `test_concurrent_tool_calls_create_exactly_one_side_effect` 6 线程 | 一致（E2） |
| “熔断状态 SQLite 共享，单机多 worker 可见” | `SqliteCircuitStore` 存在；测试是同进程两个 `CircuitBreaker` 实例，不是两个进程 | **部分一致**：实现存在，证据不足 |
| “启动时把心跳过期的 running 标为 interrupted” | `mark_stale_running()` 用的是 `updated_at`，不是 `heartbeat_at`；`heartbeat()` 从未被调用 | **不一致**：应改为“updated_at 超时扫描” |
| “本项目用请求/心跳与状态机约束同一 task_id 只有一个执行者” | 没有任务租约；`/resume` 先读后写，存在并发窗口 | **不一致**：不能声称单写者 |
| “Trace 每个节点一条事件，含 duration_ms” | 节点事件只有 `at`；`duration_ms` 只在工具结果里；`trace_event()` 未被调用 | **不一致** |
| “预算耗尽进入 partial + task_deadline_exceeded” | `_check_deadline()` 抛 `TaskTimeout("任务总超时…")`，`stop_reason` 是中文消息 | **部分不一致**：状态是 partial，reason 不稳定 |
| “401 只调用一次且不走 fallback” | 测试断言通过 | 一致（E1） |
| “429 的 sleep 等于 Retry-After” | 测试断言通过 | 一致（E1） |
| “审批并发只有一个成功” | `transition_status` 条件 UPDATE；两线程测试 | 一致（E2） |
| “真实模型未验证” | 全部测试 `MOCK_LLM=1`；无 Key | 一致（诚实） |
| “Gradio/MCP/Docker 未验证” | 未安装/未启动 | 一致（诚实） |

**结论**：v2 教程在两处“能力表述”上超过了代码证据：**心跳/租约**与**节点耗时 Trace**；另有一处 `stop_reason` 与文档不一致。这三处必须在 v3 文档中降级表述，不能继续沿用。

## 4. 测试质量评估

### 4.1 64 个测试证明了什么

| 能力 | 证据强度 | 说明 |
|---|---|---|
| ReAct 循环确实回灌观察 | 强 | 第二次决策的输入被断言包含第一次工具结果 |
| 预算能刹车 | 强 | 7 次工具脚本 + `max_steps=2`，断言 `partial`、`stop_reason`、观察数 |
| 401 不重试、429 遵守 Retry-After | 强 | 假客户端精确计数/睡眠 |
| 熔断三态与单探针 | 强 | 8 线程 barrier，断言 1 admitted / 7 rejected |
| 工具幂等并发唯一副作用 | 强 | 6 线程同一 key，文件数=1 |
| 崩溃后恢复不重复副作用 | 强 | 真实子进程崩溃 + 新进程恢复 |
| 审批跨重启 | 强 | 关闭 saver、重建 graph |
| 审批原子迁移 | 中 | 两线程条件 UPDATE；不是 HTTP 并发 |
| API 错误契约/限流/认证 | 中 | TestClient，非真实网络 |

### 4.2 64 个测试没有证明什么

1. **真实模型的质量、延迟、限流行为**：所有 LLM 测试都用 `FakeClient` 或 `MockDecider`。
2. **任务级并发**：没有两个 worker 同时跑同一 task 的测试。
3. **并发 `/resume`**：没有这个测试；代码也没有原子领取。
4. **`mark_succeeded` 失败**：没有测试；代码吞异常。
5. **HALF_OPEN 探针崩溃**：没有测试；代码会永久占位。
6. **跨用户 `Idempotency-Key`**：没有测试；探针已复现。
7. **`GET /tasks` 用户隔离**：没有测试；探针已复现。
8. **checkpoint 保存失败**：没有故障注入点。
9. **取消运行中任务**：没有接口。
10. **1 GiB 上传/内存压力/soak**：没有做。
11. **Docker/MCP/Gradio/CI**：没有实际运行。
12. **节点耗时/模型调用 ID/Token 归因**：Trace 没有这些字段，测试也没有断言。

### 4.3 测试设计上的两个好习惯

- 故障注入用**真实子进程**而不是 monkeypatch 模拟崩溃，证据强度高。
- 并发测试用 `threading.Barrier` 而不是顺序调用，能真实触发竞争。
- 断言不只看 `status`，还看文件数、`replayed`、`attempts`、`stop_reason`，这是“行为测试”而不是“覆盖率测试”。

## 7. 最薄弱的三个地方

### 7.1 任务层没有“单写者”语义

- 没有 `pending` 队列、没有 worker 租约、没有运行中心跳、没有取消。
- `/resume` 是“读状态 → 写 running → invoke”，不是原子领取。
- `mark_stale_running` 只在启动时扫 `updated_at`，可能误伤另一个 worker 正在跑的任务。
- 幂等只保护副作用工具，不阻止两个 worker 同时跑 LLM/读工具/写状态。

**影响**：一旦真的开两个 worker，任务可能重复执行、状态互相覆盖；这不是“加个 Redis 就好了”，而是任务生命周期模型缺失。

### 7.2 真实模型与评测是空白

- 所有测试 `MOCK_LLM=1`；`FakeClient` 只验证传输层分支，不验证模型是否选对工具、是否遵守 Schema、是否完成业务目标。
- `scripts/evaluate.py` 把 `pending_approval` 算成功，没有工具选择准确率、步骤数、Token、延迟、恢复率。
- 没有记录模型版本/Prompt 版本/配置快照，无法做回归比较。

**影响**：无法回答“这个 Agent 到底好不好”，只能回答“控制流是否按预期走”。

### 7.3 文档能力表述超过代码证据

- “心跳/租约”“节点 duration”“task_deadline_exceeded”三处与代码不一致。
- README 把“64 个测试”当作整体质量证据，但没有说明 64 个都是 Mock。
- 这会直接伤害面试可信度：面试官一追问“心跳在哪调用的”，就会露馅。

**影响**：不是技术缺陷，是**可信度缺陷**；比缺功能更值得优先修。

## 8. 如果目标是 Agent 开发实习，最值得投入的五项

按投入产出比排序，不做“技术栈堆砌”：

1. **修 P0 正确性/越权问题**（1–2 天）
   - `Idempotency-Key` 加 `user_id` 作用域；
   - `GET /tasks` 按 user 过滤；
   - `/resume` 用条件 UPDATE 原子领取；
   - `mark_succeeded` 失败不再吞异常。
   - 产出：4 个回归测试 + 1 篇“缺陷定位”笔记。

2. **补任务租约/心跳/取消的最小闭环**（3–5 天）
   - `owner / lease_expires_at / heartbeat_at`；
   - 运行中定期续租；
   - reaper 周期回收；
   - `POST /tasks/{id}/cancel` + 工具层 cancel token。
   - 产出：并发/崩溃/取消测试；这是从“机制”到“系统”的关键一步。

3. **做真实评测的最小版本**（3–5 天）
   - 30–50 条固定任务集；
   - 指标：完成率、工具选择准确率、无效调用率、平均步数、Token、P95 延迟、恢复率；
   - 记录模型/Prompt/配置版本；
   - Mock 与 Real 分开报告。
   - 产出：`eval_report.json` + 一页对比表；**没有数据就不要写提升百分比**。

4. **补可观测性字段**（2–3 天）
   - 每节点 `start/end/duration`；
   - `trace_id/span_id/node_id/model_call_id`；
   - 每任务 Token 归因；
   - 用 `trace_event()`/`Stopwatch` 落地，删死代码。
   - 产出：一次失败任务的定位演示。

5. **跑一次真实模型 + Docker**（1–2 天，取决于 Key/环境）
   - `scripts/test_llm.py` 真实调用；
   - 3 个模型/2 个 Prompt 版本的小样本对比；
   - Docker Compose 起 API + Redis，验证 `/ready`、重启恢复。
   - 产出：真实日志/截图/报告；仍不宣称“生产级”。

**不建议现在做**：Kafka、Celery、Kubernetes、自治 Multi-Agent、向量数据库、完整 RBAC。它们不解决当前最薄弱的“任务单写者 + 真实评测”。

## 9. 文档升级方案（基于审查）

v2 教程的 19 章结构是合理的，但缺少四个必须补的章节：

1. **任务生命周期与调度**：状态机、合法迁移、取消、租约、心跳、reaper；明确“当前没有队列”。
2. **并发与持久化架构**：SQLite 的限制、WAL、写放大、多 worker 风险、Postgres 演进触发条件。
3. **Agent 效果评测**：指标定义、数据集、版本记录、Mock/Real 分离、回归比较；不编造结果。
4. **系统级测试**：真实模型、并发、崩溃、checkpoint 失败、取消；给出测试目的/输入/注入/预期/验收/代码位置。

同时做三件事：

- **降级表述**：心跳/租约、节点耗时、`task_deadline_exceeded` 按代码事实改写。
- **区分“已实现/部分实现/规划中”**：每章开头加“能力状态”小表。
- **把审查证据写进教程**：不是“我们实现了”，而是“哪个文件、哪个测试、哪个边界”。

v3 教程采用 20 章 + 4 附录；审查报告、完成度清单、问题清单、测试方案、面试题、简历、路线图作为独立交付物，互相引用同一组事实。

## 10. 审查结论

- **可以讲**：ReAct 有界循环、五类预算、分类重试、Retry-After、三态熔断单探针、SQLite 幂等认领/对账、LangGraph 检查点恢复、真实子进程崩溃测试、6 线程并发副作用测试。
- **只能谨慎讲**：单机多进程共享熔断（实现有，证据不足）、审批并发（有原子迁移，但没有 HTTP 级并发测试）、Memory 分层（有，但词法召回）。
- **不能讲**：生产级、分布式、Exactly-once、真实模型准确率、多 Agent 协作、完整多租户、任务队列/租约。
- **最该修**：跨用户幂等键、列表越权、`/resume` 非原子、`mark_succeeded` 吞异常。
- **最该补**：任务租约/心跳/取消、真实模型评测、节点级 Trace。

> 本报告中的所有“通过”均来自 2026-11-04 的实际执行；所有“未验证”均明确标注，不用文档自述替代证据。

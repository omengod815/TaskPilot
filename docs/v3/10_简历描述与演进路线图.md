## 一、简历项目描述

### 版本 A：3 条（适合一页简历，空间紧张）

> **TaskPilot Agent Platform｜Agent 工程化升级（个人项目）**
>
> - 将固定 Planner→Tool→Writer 流程重构为有界 ReAct 循环：结构化动作决策、白名单工具执行、Observation 回写与条件边；用步数/工具/模型/Token/总 deadline 五类硬预算约束执行，耗尽返回明确 `partial` 终态。
> - 实现分类重试与三态熔断：401/403/参数错误不重试，429 尊重 `Retry-After`，半开单探针；主模型不可用切备用模型，检索不可用回退本地知识库，降级结果显式标记。
> - 基于 SQLite 唯一约束 + `BEGIN IMMEDIATE` 实现工具幂等（IN_PROGRESS/SUCCEEDED/FAILED/UNKNOWN、参数摘要、租约、对账），结合 LangGraph `SqliteSaver` 实现断点恢复；64 个测试覆盖真实子进程崩溃与 6 线程并发副作用。

### 版本 B：5 条（推荐，技术细节更完整）

> **TaskPilot Agent Platform｜Agent 工程化升级（个人项目）**
>
> - **执行控制**：把固定流水线重构为 `react_decide ⇄ tool_execution` 有界循环；模型只输出结构化 `ActionDecision`，应用层做工具白名单、Pydantic 参数校验、权限与审批；五类硬预算（步数/工具/模型/Token/绝对 deadline）在资源消耗前扣减，耗尽返回 `partial + stop_reason`。
> - **故障处理**：按错误分类决定重试/降级/熔断；401/403/参数/业务冲突不重试，429 读取 `Retry-After`，非幂等超时不重试；关闭 SDK 自带重试，避免 3×3 放大；CLOSED/OPEN/HALF_OPEN 三态熔断，半开单探针；主模型失败切备用模型，检索失败回退本地知识库，降级结果显式标记。
> - **副作用一致性**：用 `sha256(task_id+tool+canonical(args))` 生成稳定幂等键；SQLite 唯一键 + `BEGIN IMMEDIATE` 原子认领；状态机 IN_PROGRESS/SUCCEEDED/FAILED/UNKNOWN；参数摘要防误去重；租约过期先对账再重试；结果持久化供重放。
> - **断点恢复与可观测性**：LangGraph `SqliteSaver`，`thread_id=task_id`；每个 super-step 写检查点；`/resume` 从待执行节点继续；工具成功但检查点未写的窗口由幂等记录闭合；JSON 日志 + request/task/thread ID + 每节点 Trace + `/metrics`。
> - **测试**：从 11 个扩展到 64 个，覆盖预算耗尽、429/401、熔断切换、检索降级、6 线程并发副作用、UNKNOWN 对账、审批跨重启、真实子进程 `os._exit(42)` 崩溃恢复；全部离线可复现（`MOCK_LLM=1`）。

### 版本 C：一句话（用于自我介绍/项目列表）

> “把一个固定流水线的 LangGraph Agent 项目升级为有界 ReAct + 分类重试 + 三态熔断 + SQLite 工具幂等 + 检查点恢复的单机工程原型，用 64 个测试（含真实子进程崩溃/6 线程并发）验证执行可控与副作用不重复。”

## 二、30 秒 / 2 分钟口述

### 30 秒

> “TaskPilot 是我做的一次 Agent 工程化升级。原项目是固定的 Planner→Tool→Writer 流程；我把它改成有界 ReAct 循环：模型只提出结构化动作，应用层做白名单、参数校验、预算和权限控制，工具结果回写后再决策。可靠性上实现了分类重试、三态熔断、SQLite 工具幂等和 LangGraph 检查点恢复，并用 64 个测试验证，其中包含真实子进程崩溃和 6 线程并发副作用。它是单机 SQLite 的工程原型，不是生产系统。”

### 2 分钟

按“原问题 → 四个改动 → 证据 → 限制”：

1. **原问题**：固定流水线没有观察回馈；没有硬预算；工具无幂等；崩溃只能重跑。
2. **改动一**：`react_decide ⇄ tool_execution` 循环，`ActionDecision` 结构化，五类预算，deadline 绝对时间。
3. **改动二**：分类重试（401/403 不重试、429 读 Retry-After）+ 三态熔断（半开单探针）+ 降级显式标记。
4. **改动三**：SQLite 唯一键 + `BEGIN IMMEDIATE` 幂等认领（四状态、参数摘要、租约、对账）+ Checkpoint 恢复。
5. **证据**：64 passed；真实子进程崩溃；6 线程并发；审批跨重启。
6. **限制**：单机 SQLite、同步执行、无任务租约/取消、真实模型未验证、无多租户。

## 五、不做什么（以及为什么）

| 技术 | 现在不做 | 触发条件 |
|---|---|---|
| Kafka | 没有多消费者/回放/削峰 | 需要事件驱动/多订阅者 |
| RabbitMQ | 没有复杂路由/延迟队列 | 需要可靠消息/死信 |
| Celery | 同步执行够用 | 需要分布式 worker/定时任务 |
| Redis | 单机状态够用 | 多实例共享限流/熔断/锁 |
| Postgres | 数据量/并发不够 | 多主机/多租户/高并发写 |
| 向量数据库 | 语料只有一份知识库 | 语义召回成为瓶颈 |
| 自治 Multi-Agent | 单 Agent 可完成 | 任务可分解且收益可评测 |
| OpenTelemetry | JSON 日志/本地指标够用 | 多实例/跨服务排障 |
| Kubernetes | 单机部署够用 | 多副本/弹性/灰度 |

## 六、最终结论（诚实回答六个问题）

### 1. 当前 TaskPilot 的真实技术水平处于什么阶段？

**L2–L3 之间**：机制层（ReAct/预算/重试/熔断/幂等/恢复）接近 L3；系统层（任务调度/租约/取消/多租户/真实评测）仍是 L2。它不是生产级系统，也不是“只会跑 Demo”的玩具。

### 2. 哪些设计已经有实际代码支持？

- 有界 ReAct 循环；
- 五类预算（deadline reason 待修）；
- 分类重试 + Retry-After；
- 三态熔断 + 半开单探针；
- SQLite 工具幂等（认领/冲突/重放/租约/对账）；
- LangGraph 检查点恢复；
- 审批状态机 + 原子迁移；
- 请求幂等（有跨用户缺陷）；
- Memory 分层/TTL/去重；
- 结构化日志/Trace/指标（字段不全）；
- 64 个离线测试（含真实崩溃/并发）。

### 3. 哪些设计缺少测试证据？

- 真实模型质量/限流/超时；
- 任务级并发/租约/心跳；
- 并发 `/resume`；
- `mark_succeeded` 失败；
- HALF_OPEN 探针崩溃；
- checkpoint 保存失败；
- 跨用户幂等键/列表隔离（已用探针复现缺陷）；
- 熔断跨进程共享（测试是同进程两对象）；
- Docker/MCP/Gradio/CI；
- 1GiB 上传/soak。

### 4. 哪些功能目前不值得继续增加？

Kafka、RabbitMQ、Celery、Kubernetes、自治 Multi-Agent、向量数据库、完整 RBAC、OpenTelemetry Collector。它们不解决当前最薄弱的“任务单写者 + 真实评测”。

### 5. 当前项目最薄弱的三个地方是什么？

1. **任务层没有单写者**：无队列/租约/心跳/取消，`/resume` 非原子。
2. **真实模型与评测空白**：所有测试 Mock，无法回答“Agent 好不好”。
3. **文档能力表述超过代码**：心跳/节点耗时/deadline reason 三处不一致。

### 6. 如果目标是 Agent 开发实习，最值得投入时间的五项改进是什么？

1. 修 P0（跨用户幂等键、列表越权、resume 原子、mark_succeeded）。
2. 任务租约/心跳/reaper/取消的最小闭环。
3. 真实评测最小版本（30–50 条 + 8 指标 + 版本记录）。
4. 节点耗时/模型调用 ID/Token 归因。
5. 跑一次真实模型 + Docker，留下可复现证据。
